####  9.7.18.2. Matrix and Data Movement Shape

There are two kinds of shapes involved.

  1. Shapes in the data movement operations

  2. Shapes in the MMA operations

<a id="tcgen05-matrix-shape"></a>

<a id="id480"></a>

#####  9.7.18.2.1. Matrix Shape

The matrix multiply and accumulate operations support a limited set of shapes for the operand matrices `A`, `B` and `D`. The shapes of all three matrix operands are collectively described by the tuple _MxNxK_ where `A` is _MxK_ matrix, `B` is a _KxN_ matrix, and `D` is a _MxN_ matrix.

<a id="tcgen05-matrix-shape-target-isa-note"></a>

<a id="id481"></a>

######  9.7.18.2.1.1. Target ISA Note

  * K = 96 is only supported for following architecture-specific targets:

    * `sm_103a`.

    * `sm_107a`

  * K = 64 for Dense matrix and K = 128 for Sparse matrix with `.kind::f8f6f4`/`.kind::mxf8f6f4` supported on following family-specific architectures:

    * `sm_107f` or higher in the same family

  * K = 128 for Dense matrix and K = 192 for Sparse matrix with `.kind::mxf4`/`.kind::mxf4nvf4` supported on following family-specific architectures:

    * `sm_107f` or higher in the same family

<a id="tcgen05-specify-matrix-shape"></a>

<a id="id482"></a>

#####  9.7.18.2.2. Specifying Matrix Shape

_M_ and _N_ can be specified in the [Instruction descriptor](9.7.18.4-matrix-descriptors.md#tcgen05-instruction-descriptor).

_K_ can be specified explicitly if there are multiple values of _K_ supported for a given MMA variant. Otherwise, if _K_ can be uniquely determined as per the [Table 48](#tcgen05-kind-shapes), then the instruction descriptor bit corresponding to _K_ must be set to 0.

<a id="tcgen05-data-movement-shape"></a>

<a id="id483"></a>

#####  9.7.18.2.3. Data Movement Shape

The data movement shape indicates the dimension of the data to be moved to or from the [Tensor Memory](9.7.18.1-tensor-memory.md#tensor-memory). These shapes are described as a tuple `lane x size` where:

  * `lane` indicates the number of rows in the [Tensor Memory](9.7.18.1-tensor-memory.md#tensor-memory); and

  * `size` indicates the amount of data, in units of bits (b), across the columns in the [Tensor Memory](9.7.18.1-tensor-memory.md#tensor-memory).

The following shapes are supported by various tcgen05 operations:

Shape | tcgen05.<op>
---|---
`.16x64b`, `.16x128b`, `.16x256b`, `.16x32bx2`, `.32x32b` | `.ld` / `.st`
`.4x256b`, `.32x128b`, `.64x128b`, `.128x256b`, `.128x128b` | `.cp`
`.31x256b` (implicit) | `.shift`

<a id="tcgen05-memory-layout"></a>

<a id="id484"></a>

######  9.7.18.2.3.1. Memory Layout

The following shows the layout of the matrix fragments across threads of the warp.

###### 9.7.18.2.3.1.1. Matrix fragments for shape .32x32b

A `tcgen05{.ld,.st}.32x32b` instruction has the following data vector register.

Fragment | Elements (low to high)
---|---
A vector expression containing `.num` number of `.b32` registers as mentioned in the [Table 59](9.7.18.8-tensor-memory-and-register-loadstore-instructions.md#tcgen05-num-shapes-ld). | r0, r1, …

A warp executing `tcgen05{.ld,.st}.32x32b` will access 32 lanes of the Tensor Memory. It loads from or stores to each of the lane (32 * .num)-bits of data as shown in [Figure 186](#tcgen05-mma-fragment-3232b).
